# Feature requests

Search [existing proposals](https://github.com/qpiai/qpiai-opt/issues), then use the [feature request form](https://github.com/qpiai/qpiai-opt/issues/new?template=feature_request.yml).

A proposal should describe a concrete optimization workflow and how the requested capability fits the SDK's modelling, solving, or interoperability API. Include:

- the developer, research, production, or automation workflow it unlocks;
- why existing capabilities or a trivial adapter are insufficient;
- expected mathematical semantics and supported problem class;
- local-versus-platform behavior and whether paid work is possible;
- the proposed public API;
- compatibility, test, and documentation consequences.

Prefer a focused adapter or representation option over a new symbolic system, provider framework, CLI, or domain-specific object hierarchy.
